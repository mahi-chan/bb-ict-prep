    Build-heap works bottom-up: start at the last non-leaf (index 3 for n = 8) and heapify down through index 0. Each heapify swaps a node with its smallest child if needed, then recurses into the child's subtree.

    1. Heapify index 3 (node 12). Children: 5. Since 5 < 12, swap → [40, 25, 60, 5, 8, 35, 50, 12].

    2. Heapify index 2 (node 60). Children: 35, 50. Since 35 < 60, swap → [40, 25, 35, 5, 8, 60, 50, 12].

    3. Heapify index 1 (node 25). Children: 5, 8. Since 5 < 25, swap → [40, 5, 35, 25, 8, 60, 50, 12]. Recurse into index 3 (now 25). Children: 12. Since 12 < 25, swap → [40, 5, 35, 12, 8, 60, 50, 25].

    4. Heapify index 0 (node 40). Children: 5, 35. Since 5 < 40, swap → [5, 40, 35, 12, 8, 60, 50, 25]. Recurse into index 1 (now 40). Children: 12, 8. Since 8 < 40, swap → [5, 8, 35, 12, 40, 60, 50, 25]. Recurse into index 4 (now 40). No children violate. Done.

    Final min-heap array: [5, 8, 35, 12, 40, 60, 50, 25]

    Build-heap is O(n), not O(n log n), because most nodes are near the bottom and heapify down from each only a few levels.

    Given
    • L = 1500 bytes = 12,000 bits
    • B = 10 Mbps = 10⁷ bps
    • d = 300 km = 300,000 m; v = 2 × 10⁸ m/s
    • 3 routers → 4 links; per-router delay = 0.5 ms processing + 1 ms queuing = 1.5 ms

    1. Transmission delay:

      Tt = L / B = 12,000 / 10⁷ = 1.2 ms

    2. Propagation delay:

      Tp = d / v = 300,000 / (2 × 10⁸) = 1.5 ms

    3. Total one-way latency (store-and-forward):

      = 4 × 1.2 ms + 1.5 ms + 3 × 1.5 ms = 4.8 + 1.5 + 4.5 = 10.8 ms

    4. RTT = 2 × 10.8 = 21.6 ms

    5. Bandwidth-delay product:

      BDP = B × Tp = 10⁷ × 1.5 × 10⁻³ = 15,000 bits = 1,875 bytes

    6. Stop-and-wait efficiency:

      η = Tt / (Tt + RTT) = 1.2 / (1.2 + 21.6) = 5.26%

    Recall: A → B is false only when A is true and B is false. We build the table for all combinations of p and q:

    p q q → p p → (q → p)
    TTTT
    TFTT
    FTFT
    FFTT

    The final column is T in every row. Therefore p → (q → p) is a tautology.

    Intuition: "if p is true, then no matter what q is, p is still true." The only danger is row 3 (p = F), but F → anything is vacuously true.

    Yes — a single process can deadlock itself. The four Coffman conditions can all hold with one process:

    1. Mutual exclusion: the resource is non-sharable (e.g. a non-reentrant lock).

    2. Hold and wait: the process holds the lock and requests the same lock again.

    3. No preemption: the OS cannot forcibly reclaim the lock.

    4. Circular wait: the resource allocation graph has a self-loop — the process waits for a resource it already holds.

    Example: a process acquires a non-recursive mutex, then calls a function that attempts to acquire the same mutex. It blocks waiting for itself — a deadlock of one.

    1. Number of blocks:

    4. Index bits: log₂(128) = 7 bits

    5. Tag bits: 32 − 7 − 6 = 19 bits

    6. Total bits per block: valid (1) + tag (19) + data (64 × 8 = 512) = 532 bits

    7. Total cache bits:

      Total = 512 blocks × 532 bits = 272,384 bits = 34,048 bytes ≈ 33.25 KB

    Final answer: 6 offset, 7 index, 19 tag bits; total ≈ 272,384 bits (33.25 KB).
