    1. Von Neumann and Harvard architecture

    The Von Neumann architecture stores both instructions and data in the same memory, accessed through a single bus. This is elegant but creates a bottleneck — the CPU cannot fetch an instruction and read data at the same time. The Harvard architecture uses separate memories and buses for instructions and data, allowing simultaneous access.

    FeatureVon NeumannHarvard
    MemorySingle (shared)Separate instruction + data
    BusSingle bus → bottleneckDual buses → parallel access
    SpeedSlower (bus contention)Faster (simultaneous fetch)
    ComplexitySimpler hardwareMore complex (two memories)
    Used inGeneral-purpose PCsDSPs, microcontrollers, caches
    Key registersPC (Program Counter), IR (Instruction Register), MAR (Memory Address Register), MBR (Memory Buffer Register), ACC (Accumulator).
    Stored-program conceptInstructions are stored in memory as data and can be modified — the foundation of all modern computing.

    2. Instructions and addressing modes

    3. Computer arithmetic — Booth's and IEEE 754

    The exam asks you to multiply signed binary numbers using Booth's algorithm and to encode/decode floating-point numbers in IEEE 754 format. Both require a step-by-step trace.

    Booth's multiplication

    Multiply 7 × (−3) using Booth's algorithm (4-bit) 
    M  = 7  = 0111     (multiplicand)
Q  = -3 = 1101     (multiplier, 2's complement)
-M = 1001           (2's complement of M)

  A       Q      Q₋₁   Operation
0000    1101      0     Start
Step 1: Q₀Q₋₁ = 10 → A = A − M = 0000 + 1001 = 1001
        1001    1101    0

Step 2: Q₀Q₋₁ = 11 → no operation
        ASR:  1110  0111    0

        0111    0111    0
        ASR:  0011  1011    1
Step 4: Q₀Q₋₁ = 11 → no operation
        ASR:  0001  1101    1

Result: A|Q = 0001 1101 → but we need 8 bits for −21.

    4. Performance — CPU time and Amdahl's law

    The exam gives you clock rate, CPI and instruction count, then asks for CPU time or speedup. Amdahl's law questions are especially common.

    CPU time= Instruction count × CPI × Clock cycle time = (IC × CPI) / Clock rate
    CPICycles Per Instruction. Lower is better. Average CPI = Σ(CPIi × fi) where fi is the frequency of instruction type i.
    MIPS= IC / (Execution time × 10⁶) = Clock rate / (CPI × 10⁶)
    Worked example — CPU time 
    Given: IC = 10⁹ instructions, CPI = 2.5, Clock rate = 2 GHz

CPU time = IC × CPI / Clock rate
         = 10⁹ × 2.5 / (2 × 10⁹)
         = 2.5 / 2
         = 1.25 seconds

    Amdahl's law

    FormulaSpeedup = 1 / [(1 − f) + f/S] where f = fraction enhanced, S = speedup of enhanced part.
    Worked example — Amdahl's law 
    A program spends 40% of its time on floating-point operations.
You improve the FP unit to run 10× faster. Overall speedup?

f = 0.4, S = 10
Speedup = 1 / [(1 − 0.4) + 0.4/10]
        = 1 / [0.6 + 0.04]
        = 1 / 0.64
        = 1.5625×

Even with a 10× FP speedup, the overall speedup is only 1.56×
because 60% of the program is unaffected.
    Amdahl's limit. As S → ∞, the speedup approaches 1/(1 − f). With f = 0.4, the maximum possible speedup is 1/0.6 = 1.667×, no matter how fast the FP unit becomes. The non-enhanced portion is the bottleneck.

    5. Pipelining and hazards

    Pipelining overlaps the execution of multiple instructions — while one instruction is in the execute stage, the next is decoding, and the one after that is being fetched. The exam tests speedup formulas and hazard identification.

    Ideal speedup= k (number of stages), when pipeline is full. With n instructions: time = k + (n − 1) cycles.
    Throughput= n / [k + (n − 1)] instructions per cycle. Approaches 1 as n → ∞.
    Pipeline hazards
    HazardCauseSolution
    StructuralTwo instructions need the same hardware (e.g., memory port)Duplicate hardware, separate I/D caches
    Data (RAW)Instruction needs result of a previous instruction not yet writtenForwarding (bypassing), stalling
    Data (WAR, WAW)Write-after-read or write-after-write ordering issuesRegister renaming
    ControlBranch target unknown — wrong instructions may have been fetchedBranch prediction, delayed branch, flush

    6. Cache memory and mapping

    Cache sits between the CPU and main memory, holding recently-used data for fast access. The exam tests three mapping techniques and the total-bits calculation for cache storage.

    Cache mapping — address bit-field splits
    MappingAddress fieldsPlacement
    DirectTag | Line (Index) | OffsetEach block maps to exactly one cache line
    Fully associativeTag | OffsetAny block can go in any line
    Set associativeTag | Set index | OffsetBlock maps to a specific set, any line within that set
    Worked example — direct-mapped cache bit-field split 
    Given: Main memory = 64 KB (16-bit address), Cache = 1 KB,
       Block size = 16 bytes

Offset bits  = log₂(16)         = 4 bits
Cache lines  = 1024 / 16        = 64 lines
Index bits   = log₂(64)         = 6 bits
Tag bits     = 16 − 6 − 4       = 6 bits

Address: [Tag: 6 | Index: 6 | Offset: 4]
    AMATAverage Memory Access Time = Hit time + (Miss rate × Miss penalty)
    Worked example — AMAT 
    Hit time = 1 ns, Miss rate = 5%, Miss penalty = 100 ns

AMAT = 1 + (0.05 × 100) = 1 + 5 = 6 ns
    Write-throughWrite to both cache and memory. Simple but slow for writes.
    Write-backWrite to cache only; update memory when line is evicted (dirty bit). Faster, more complex.
    LRULeast Recently Used replacement — evict the line that hasn't been accessed for the longest time.

    7. Main and virtual memory

    Virtual memory allows programs to use more memory than physically available by mapping virtual addresses to physical addresses through a page table. The TLB (Translation Lookaside Buffer) caches recent translations to speed this up.

    Page table size= (Virtual address space / Page size) × Entry size
    Worked example — page table 
    Virtual address = 32 bits, Page size = 4 KB, Entry = 4 bytes

Number of pages = 2³² / 2¹² = 2²⁰ = 1,048,576 pages
Page table size = 2²⁰ × 4 bytes = 4 MB

Virtual address split: [Page number: 20 | Offset: 12]
    TLBSmall, fast, fully-associative cache of page table entries. TLB hit → 1 memory access. TLB miss → 2 accesses (page table + data).
    EATEffective Access Time = h × t + (1−h)(t + m) where h = TLB hit ratio, t = TLB access time, m = memory access time.
    Page faultPage not in physical memory → OS fetches from disk. Very expensive (~10 ms vs ~100 ns memory access).

    8. Secondary storage and disk timing

    The exam asks you to calculate disk access time, which has three components: seek time, rotational latency and transfer time.

    Access time= Seek time + Rotational latency + Transfer time
    Rotational latencyAverage = ½ × (60 / RPM) seconds = time for half a rotation.
    Transfer time= Data size / Transfer rate. Or: (Bytes per track) / (RPM/60) for one track.
    Worked example — disk access time 
    Given: RPM = 7200, Avg seek = 8 ms, Block size = 4 KB,
       Transfer rate = 100 MB/s

Rotational latency = ½ × (60/7200) = ½ × 8.33 ms = 4.17 ms
Transfer time      = 4 KB / 100 MB/s = 4096 / (100 × 10⁶)
                   = 0.04 ms

Access time = 8 + 4.17 + 0.04 = 12.21 ms

    9. I/O organisation

    Three methods move data between I/O devices and memory. The exam asks you to compare them and to explain DMA.

    I/O transfer methods
    MethodCPU involvementEfficiency
    Programmed I/OCPU polls device status continuouslyWorst — CPU wastes cycles waiting
    Interrupt-driven I/OCPU works; device signals when readyBetter — CPU is free between interrupts
    DMADMA controller transfers data directly to memoryBest — CPU involved only at start and end
    DMA modesCycle stealing: DMA takes one bus cycle per word, interleaving with CPU. Burst mode: DMA takes bus for entire transfer — faster but blocks CPU.
    Memory-mapped I/OI/O devices share the address space with memory. Read/write to a memory address actually communicates with the device.
    Isolated I/OSeparate address space for I/O. Special instructions (IN/OUT) are needed. Used in x86.

    10. Microprocessors — 8085 and 8086

    The exam asks for architecture diagrams, register sets and comparisons of the 8085 (8-bit) and 8086 (16-bit) processors.

    8085 vs 8086
    Feature80858086
    Data bus8-bit16-bit
    Address bus16-bit (64 KB)20-bit (1 MB)
    RegistersA, B, C, D, E, H, L + SP, PCAX, BX, CX, DX + SI, DI, SP, BP + segment registers
    SegmentationNoYes (CS, DS, SS, ES)
    Clock3–5 MHz5–10 MHz
    PipelineNoYes (BIU + EU)
    MultiplicationNo hardware multiplyMUL/IMUL instructions
    8085 flagsS (Sign), Z (Zero), AC (Auxiliary Carry), P (Parity), CY (Carry) — 5 flags.
    8086 flagsSame 5 + O (Overflow), D (Direction), I (Interrupt), T (Trap) — 9 flags.
    8086 physical address= Segment × 16 + Offset. Example: CS=2000h, IP=1234h → PA = 20000h + 1234h = 21234h.
    BIU and EUBus Interface Unit (fetches instructions into queue) + Execution Unit (decodes and executes). This overlap is a primitive pipeline.

    11. Parallel processing and Flynn's taxonomy

    Flynn's taxonomy classifies computer architectures by the number of instruction and data streams they handle simultaneously.

    Flynn's taxonomy
    CategoryInstructionDataExample
    SISDSingleSingleTraditional uniprocessor (Von Neumann)
    SIMDSingleMultipleGPU, vector processors, array processors
    MISDMultipleSingleRare — fault-tolerant systems (space shuttle)
    MIMDMultipleMultipleMulticore CPUs, clusters, supercomputers
    MultiprocessorMultiple CPUs sharing memory (shared memory / UMA). Tightly coupled.
    MulticomputerMultiple CPUs with private memory, communicating via messages. Loosely coupled.
    MulticoreMultiple processing cores on a single chip. Shares L2/L3 cache. Standard in modern CPUs (2, 4, 8+ cores).
