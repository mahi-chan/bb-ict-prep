    Emerging Tech

    Cloud computing, big data analytics, AI/ML, IoT, blockchain and other frontier technologies — increasingly asked in the BB AD (ICT) exam, especially how they apply to banking and the Bangladesh context.

    1. Cloud computing

    Cloud computing delivers computing resources (servers, storage, databases, networking, software) over the internet on a pay-as-you-go basis.

    ModelYou manageProvider managesExample
    IaaSOS, runtime, app, dataHardware, networking, virtualisationAWS EC2, Azure VM
    PaaSApp, dataOS, runtime, middlewareHeroku, Google App Engine
    SaaSNothing (just use it)EverythingGmail, Office 365

    Deployment models:

    ModelDescriptionBanking use
    Public cloudShared infrastructure (AWS, Azure, GCP)Non-sensitive workloads, DR backup
    Private cloudDedicated to one organisationCore banking, sensitive data
    Hybrid cloudMix of public + privateMost banks: private for core, public for burst/analytics
    Community cloudShared by related organisationsGovernment cloud for BD agencies

    Key characteristics (NIST definition): on-demand self-service, broad network access, resource pooling, rapid elasticity, measured service.

    For the BB exam, emphasise that Bangladesh Bank mandates banks keep core banking data within Bangladesh. A hybrid cloud approach — private cloud for core systems, public cloud for analytics and DR — is the practical compromise.

    2. Big data and analytics

    Big data is defined by the 5 Vs:

    VMeaningBanking example
    VolumeMassive amounts of dataMillions of daily transactions
    VelocitySpeed of data generationReal-time card swipes, MFS transfers
    VarietyStructured + unstructured dataTransaction logs + customer emails + social media
    VeracityData quality and trustworthinessEnsuring KYC data is accurate
    ValueExtracting useful insightsCredit scoring, fraud patterns

    Hadoop ecosystem:

    • HDFS (Hadoop Distributed File System): stores data across many nodes with replication (default 3 copies)
    • MapReduce: parallel processing — Map (split + process) → Reduce (aggregate)
    • YARN: resource manager for the cluster
    • Spark: in-memory processing, 10–100× faster than MapReduce for iterative algorithms

    Banking applications: fraud detection (anomaly detection on transaction streams), credit risk modelling, customer segmentation, AML pattern analysis, marketing analytics.

    The exam distinction: data warehouse stores structured, cleaned, historical data for BI reporting. Data lake stores raw data (structured + unstructured) for advanced analytics. Banks increasingly use both.

    3. Artificial intelligence and machine learning

    AI is the broad field of creating intelligent machines. ML is the subset where machines learn from data without explicit programming.

    TypeDescriptionExample
    Supervised learningLabelled training data → predict labelsSpam detection (email → spam/not-spam)
    Unsupervised learningNo labels → find patternsCustomer segmentation (clustering)
    Reinforcement learningAgent learns by reward/penaltyGame playing, robotics

    Key algorithms:

    • Linear regression: predict continuous value (e.g. loan default amount)
    • Logistic regression: binary classification (approve/reject loan)
    • Decision tree / Random forest: rule-based classification, ensemble for accuracy
    • k-NN: classify based on k nearest neighbours
    • SVM: find optimal hyperplane separating classes
    • Neural network: interconnected layers of neurons, foundation for deep learning

    Deep learning uses multi-layer neural networks:

    • CNN (Convolutional Neural Network): image recognition, cheque image processing
    • RNN / LSTM: sequence data, time series (stock prices, transaction patterns)
    • Transformer: attention mechanism, foundation for GPT/BERT (NLP tasks)

    NLP (Natural Language Processing): chatbots for customer service, sentiment analysis of customer feedback, document classification, automated report generation.

    Banking AI applications: credit scoring, fraud detection, chatbots, algorithmic trading, robo-advisory, document processing (OCR on cheques), AML transaction monitoring.

    The exam likes the difference between AI, ML, and deep learning: AI ⊃ ML ⊃ Deep Learning. AI is the goal (intelligent systems), ML is the method (learn from data), DL is the technique (deep neural networks).

    4. Internet of Things

    IoT connects physical devices to the internet, enabling them to collect and exchange data without human intervention.

    IoT architecture layers:

    1. Perception layer

      Sensors, actuators, RFID tags — collect data from the physical world.

    2. Network layer

      Transmit data via Wi-Fi, Bluetooth, Zigbee, LoRa, 5G, NB-IoT.

    3. Processing layer

      Edge computing or cloud — analyse, filter, store data.

    4. Application layer

      User-facing apps — dashboards, alerts, automation.

    ProtocolUseRange
    MQTTLightweight pub/sub messagingAny (TCP/IP based)
    CoAPConstrained devices (REST-like)Any (UDP based)
    ZigbeeLow-power mesh network10–100m
    LoRaWANLong-range, low-power WAN2–15 km
    NB-IoTCellular IoT (narrow band)Cell tower range

    Banking/finance IoT: smart ATMs (sensors monitor cash levels, temperature, tampering), wearable payments (smartwatch NFC), asset tracking (collateral monitoring), smart branches (occupancy sensors, digital signage).

    IoT security challenges: resource-constrained devices can't run heavy encryption, large attack surface, firmware updates difficult, default credentials, DDoS botnets (Mirai).

    Edge computing processes data near the IoT device instead of sending everything to the cloud — reduces latency, bandwidth, and privacy risk. Critical for real-time IoT applications.

    5. Blockchain and distributed ledger

    A blockchain is a distributed, immutable ledger where transactions are grouped into blocks, each cryptographically linked to the previous one.

    1. Transaction creation

      User initiates a transaction (e.g. transfer 2 BTC).

    2. Broadcasting

      Transaction is broadcast to all nodes in the P2P network.

    3. Validation and consensus

      Nodes verify the transaction and agree on its validity (via PoW, PoS, or other mechanism).

    4. Block creation

      Valid transactions are grouped into a new block. Block header contains: previous block hash, Merkle root, timestamp, nonce.

    5. Chain addition

      New block is appended to the chain. The hash link makes tampering with any earlier block computationally infeasible.

    ConsensusMechanismUsed by
    PoW (Proof of Work)Solve cryptographic puzzle — first solver winsBitcoin
    PoS (Proof of Stake)Validators stake tokens — selected proportionallyEthereum 2.0
    PBFTVoting among known validators (≥ 2/3 agreement)Hyperledger

    Smart contracts: self-executing programs stored on blockchain. Code runs automatically when conditions are met (e.g. release payment when goods are delivered). Ethereum is the primary smart-contract platform.

    Types:

    TypeAccessUse case
    PublicAnyone can joinBitcoin, Ethereum
    PrivateSingle organisationInternal audit trail
    ConsortiumGroup of organisationsTrade finance (banks)

    Banking use cases: cross-border payments (Ripple), trade finance (letters of credit), KYC sharing between banks, supply chain finance, interbank settlement.

    For the exam: blockchain ≠ cryptocurrency. Blockchain is the technology; crypto is one application. Bangladesh bans cryptocurrency trading but recognises blockchain's potential for trade finance, land records and supply chain tracking.

    6. Frontier technologies

    Technologies on the horizon that the exam increasingly references:

    TechnologyWhat it isBanking relevance
    5G5th gen mobile: 10 Gbps, 1ms latency, massive IoTReal-time mobile banking, IoT-connected ATMs
    Quantum computingQubits (superposition + entanglement)Breaks RSA/ECC → post-quantum cryptography needed
    AR/VRAugmented/virtual reality overlaysVirtual branches, immersive training
    RPARobotic Process Automation — bots do repetitive tasksAccount opening, reconciliation, report generation
    Digital twinVirtual replica of physical systemData centre simulation, branch layout optimisation
    Zero trust"Never trust, always verify" security modelReplace perimeter security: verify every access request

    Quantum threat to banking: Shor's algorithm can factor large numbers in polynomial time → RSA, DH, ECC all break. NIST has standardised post-quantum algorithms (CRYSTALS-Kyber for encryption, CRYSTALS-Dilithium for signatures). Banks must plan for "harvest now, decrypt later" attacks.

    Classical: n bits → exactly 1 of 2n states at a time
    Quantum: n qubits → all 2n states simultaneously (superposition)
    Example: 3 qubits → 2³ = 8 simultaneous states
    50 qubits → 2⁵⁰ ≈ 1.13 × 1015 states — exceeds classical simulation
    This parallelism lets Shor's algorithm factor n-bit integers in O(n³) vs classical O(en¹ᐟ³)

    RPA in banking: automates rule-based, repetitive tasks (data entry, form filling, compliance checks). Reduces errors by 60–80%, processing time by 70–90%. Often combined with AI for "intelligent automation".

    The exam asks "what is X and how can banking use it?" For frontier tech, structure your answer as: definition → how it works (1 sentence) → banking application → challenge/risk. This template works for any emerging technology.

    S4What is blockchain? How can it be used in banking?standard repeat

    Blockchain is a decentralised, distributed, immutable ledger. Each block contains a set of transactions, a timestamp, and a cryptographic hash of the previous block.

    Banking applications:

    • Cross-border payments: faster, cheaper than SWIFT (Ripple/XRP Ledger settles in seconds vs days)
    • Trade finance: digitise letters of credit, reducing paper and fraud (Contour, we.trade)
    • KYC: shared KYC blockchain where one bank's verification is trusted by others, reducing duplication
    • Interbank settlement: real-time gross settlement on shared ledger
    • Audit trail: immutable record of all transactions for regulatory compliance

    Bangladesh context: BB has not approved cryptocurrency trading but is exploring blockchain for trade finance and supply chain tracking.

    S5What is IoT? Discuss its components and security challenges.standard repeat

    IoT = network of physical devices with sensors, software and connectivity that exchange data.

    Components: sensors/actuators (perception), communication (Wi-Fi/BLE/LoRa), processing (edge/cloud), application (user interface).

    Security challenges:

    • Resource constraints: limited CPU/memory/battery → can't run heavy encryption
    • Default credentials: many devices ship with admin/admin → Mirai botnet exploited this
    • Firmware updates: difficult to patch millions of deployed devices
    • Physical access: devices in public spaces can be tampered with
    • Large attack surface: billions of devices = billions of potential entry points
    • Data privacy: devices constantly collect data → privacy regulations apply
    S6Compare public, private and hybrid cloud. Which suits banking?standard repeat
    FeaturePublicPrivateHybrid
    InfrastructureShared (multi-tenant)Dedicated (single org)Mix of both
    CostPay-as-you-goHigh upfrontBalanced
    SecurityProvider-managedFull controlSensitive data on private
    ScalabilityVirtually unlimitedLimited by own hardwareBurst to public
    ComplianceMay not meet data residencyFull compliance controlCompliance for core data

    Banking choice: hybrid cloud is optimal — private cloud for core banking and customer data (data sovereignty, BB regulations), public cloud for DR, analytics, non-sensitive workloads and burst capacity.

    S7What is a smart contract? How does it work on blockchain?standard repeat

    A smart contract is a self-executing program stored on a blockchain that automatically enforces the terms of an agreement when predefined conditions are met.

    How it works:

    1. Parties agree on contract terms and encode them as code
    2. Code is deployed to the blockchain (e.g. Ethereum)
    3. Triggering event occurs (e.g. shipment arrives, verified by oracle)
    4. Contract auto-executes — funds are released, ownership is transferred

    Properties: immutable (can't be altered once deployed), transparent (code is visible), deterministic (same input → same output), trustless (no intermediary needed).

    Banking use: automated trade finance (release payment on delivery proof), insurance claims processing, loan disbursement on collateral verification.

    S8How is AI used in fraud detection?standard repeat

    Rule-based (traditional): if transaction > BDT 5 lakh AND overseas AND after midnight → flag. Problem: rigid rules miss new patterns and generate false positives.

    ML-based (modern):

    • Supervised learning: train on labelled fraud/non-fraud transactions → classify new transactions (logistic regression, random forest, neural networks)
    • Unsupervised learning: detect anomalies — transactions that deviate from customer's normal pattern (clustering, autoencoders)
    • Real-time scoring: each transaction gets a risk score in milliseconds; high-risk transactions are held for review
    • Network analysis: graph-based ML identifies related fraudulent accounts
    • Adaptive learning: model retrains on new fraud patterns continuously

    Advantage: ML detects novel fraud patterns that rules miss, reduces false positives by 50–60%, and scales to millions of transactions per second.

    S9What is RPA? How can banks benefit from it?standard repeat

    RPA (Robotic Process Automation) uses software bots to automate repetitive, rule-based tasks that humans currently perform.

    Bank applications:

    • Account opening — bot extracts data from submitted forms, validates against NID database, creates account in CBS
    • Loan processing — auto-collect documents, check credit scores, generate approval/rejection
    • Regulatory reporting — auto-generate BB-mandated reports from transaction data
    • Reconciliation — match transactions across systems (CBS, ATM switch, card network)
    • KYC/AML screening — auto-screen customers against sanctions lists

    Benefits: 70–90% reduction in processing time, near-zero error rate, 24/7 operation, audit trail of every action, frees staff for customer-facing work.

    S10What is quantum computing? Why is it a threat to cryptography?standard repeat

    Quantum computing uses qubits that can exist in superposition (0 and 1 simultaneously) and be entangled (correlated regardless of distance).

    Threat to cryptography:

    • Shor's algorithm: factors large numbers in polynomial time → breaks RSA, DH, ECC (all based on factoring or discrete log hardness)
    • Grover's algorithm: searches unsorted data in O(√n) → effectively halves symmetric key strength (AES-128 → 64-bit security; AES-256 → 128-bit, still safe)
    • "Harvest now, decrypt later": adversaries store encrypted data today, decrypt when quantum computers arrive

    Response: NIST post-quantum cryptography standards (2024): CRYSTALS-Kyber (key encapsulation), CRYSTALS-Dilithium, FALCON, SPHINCS+ (digital signatures). Banks should begin planning crypto-agility — the ability to swap algorithms when needed.

    Practice questions

    P1What is edge computing? How does it relate to cloud and IoT?practice

    Edge computing processes data near the source (at the "edge" of the network) rather than sending everything to a central cloud.

    Relationship:

    • IoT devices generate data → edge nodes filter, aggregate and process locally → only relevant results go to the cloud
    • Reduces latency (critical for real-time decisions), saves bandwidth, and improves privacy (raw data stays local)

    Banking example: an ATM with edge computing can detect card skimming locally (camera + ML on-device) and shut down immediately, rather than waiting for cloud analysis.

    P6What are the NIST essential characteristics of cloud computing?practice

    NIST SP 800-145 defines five essential characteristics:

    1. On-demand self-service: provision resources (servers, storage) without human interaction with the provider
    2. Broad network access: available over the network via standard mechanisms (HTTP/HTTPS, APIs)
    3. Resource pooling: provider's resources serve multiple tenants dynamically; customer doesn't control exact physical location
    4. Rapid elasticity: scale up/down automatically based on demand (appears unlimited to the user)
    5. Measured service: usage is metered, monitored, reported — pay only for what you use
    P7What is NLP? Give three banking applications.practice

    NLP (Natural Language Processing) enables computers to understand, interpret and generate human language.

    Banking applications:

    1. Chatbots and virtual assistants: handle routine queries (balance check, branch locations, loan eligibility) 24/7 — reduce call-centre load by 30–40%
    2. Sentiment analysis: monitor social media and customer feedback to detect dissatisfaction trends, identify service issues before they escalate
    3. Document processing: extract information from unstructured documents (loan applications, KYC forms, trade finance documents) — NLP + OCR automate data entry
    P8How can IoT be applied in the banking sector?practice
    • Smart ATMs: sensors monitor cash levels (predict refill schedule), detect tampering/skimming, environmental monitoring (temperature, humidity)
    • Wearable payments: smartwatches and fitness bands with NFC for contactless payment
    • Collateral monitoring: IoT sensors on financed assets (vehicles, warehouse goods) provide real-time location and status to the lending bank
    • Smart branches: people counters optimise staffing, digital signage personalises offers, environmental sensors manage energy use
    • Insurance: telematics (vehicle IoT) for usage-based insurance, health wearables for health insurance pricing
    P9What is zero trust architecture? Why is it relevant for banks?practice

    Zero trust = "never trust, always verify." Every access request is fully authenticated, authorised and encrypted, regardless of whether it comes from inside or outside the network.

    Principles:

    • Verify explicitly: authenticate and authorise based on all available data points (identity, location, device, data classification)
    • Least-privilege access: just-in-time and just-enough access
    • Assume breach: minimise blast radius, segment access, verify end-to-end encryption

    Bank relevance: after the SWIFT heist and growing insider threats, perimeter-based security ("castle-and-moat") is insufficient. Zero trust ensures that even if an attacker enters the network, they can't move laterally to critical systems like SWIFT or core banking.

    P10What is a digital twin? How could banks use it?practice

    A digital twin is a virtual replica of a physical entity (asset, process, or system) that is continuously updated with real-time data from its physical counterpart.

    Banking applications:

    • Data centre management: simulate cooling, power, and rack configurations to optimise PUE before making physical changes
    • Branch design: model customer flow, counter placement and service times to optimise branch layout
    • Stress testing: simulate market conditions, customer behaviour, and system loads to test resilience
    • ATM network: predict maintenance needs, optimise cash logistics, simulate deployment of new machines

    Technology stack: IoT sensors (data collection) + cloud (processing) + AI/ML (prediction) + visualisation (3D/dashboard).
