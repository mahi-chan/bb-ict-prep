    Security

    1. CIA triad and security goals

    The CIA triad is the foundation of information security:

    GoalMeaningThreatControl
    ConfidentialityOnly authorised parties access dataEavesdropping, data breachEncryption, access control
    IntegrityData is not altered unauthorisedTampering, MITMHashing, digital signatures
    AvailabilitySystem is accessible when neededDoS, hardware failureRedundancy, backups, DDoS protection

    Additional security properties:

    • Authentication: verifying identity (who are you?)
    • Authorisation: what are you allowed to do?
    • Non-repudiation: sender cannot deny sending (digital signatures)
    • Accountability: actions can be traced to an entity (audit logs)
    The three goals often conflict. Maximum confidentiality (encrypt everything, restrict access) can reduce availability. Maximum availability (public, always-on) reduces confidentiality. Security design is about balancing these trade-offs for the specific context.

    2. Malware types

    TypeHow it worksKey characteristic
    VirusAttaches to host file; executes when file runsNeeds host program; self-replicating
    WormSelf-replicates across networksNo host needed; spreads autonomously
    TrojanDisguised as legitimate softwareNo self-replication; relies on user to install
    RansomwareEncrypts files; demands ransom for decryption keyMajor threat to banking; WannaCry, Petya
    SpywareSilently monitors and collects user dataKeyloggers, screen capture
    RootkitHides itself and other malware deep in OSVery hard to detect; often kernel-level
    AdwareDisplays unwanted advertisementsUsually bundled with free software
    Logic bombTriggers malicious action on a condition (date, event)Dormant until triggered
    The critical distinction: a virus needs a host program to attach to, a worm is standalone and self-propagating, and a Trojan neither replicates nor infects — it tricks the user into running it. This is the most-asked malware question.

    AttackMechanismDefence

    Man-in-the-MiddleIntercept and possibly alter communicationTLS/SSL, certificate pinning

    DDoS uses a botnet (thousands of compromised machines) to generate traffic. The SYN flood specifically exploits the TCP three-way handshake — the attacker sends SYN but never completes with ACK, filling the target's half-open connection table.

    Buffer overflowMemoryOverwrite return address on stackBounds checking, ASLR, DEP

    SQL injection — vulnerable vs safe query 
    -- Vulnerable: user input concatenated into SQL
SELECT * FROM users WHERE name='' OR 1=1 --' AND pass=''
-- OR 1=1 is always true → returns ALL rows → authentication bypass

-- Safe: parameterised query (prepared statement)
PreparedStatement ps = conn.prepareStatement(
    "SELECT * FROM users WHERE name=? AND pass=?");
ps.setString(1, username);   // bound separately, never parsed as SQL
ps.setString(2, password);

    SQL injection remains the most dangerous and most-asked application attack. The defence is simple: never concatenate user input into SQL strings — always use parameterised queries (prepared statements).

    5. Social engineering

    Social engineering exploits human psychology rather than technical vulnerabilities.

    TechniqueHow it works
    PhishingFake emails/websites mimicking legitimate ones to steal credentials
    Spear phishingTargeted phishing aimed at a specific person/organisation
    WhalingPhishing targeting executives (CEO, CFO)
    VishingVoice-based phishing (phone calls)
    SmishingSMS-based phishing
    PretextingFabricated scenario to gain trust and extract information
    BaitingLeaving malware-infected media (USB) for victim to find
    TailgatingFollowing authorised person through secured entrance
    Shoulder surfingWatching someone enter credentials or PINs
    Social engineering is the hardest attack to defend against technically because it targets people, not systems. The primary defence is security awareness training. For banking, the Bangladesh Bank SWIFT heist (2016, $81M stolen) used spear phishing as the initial entry point.

    6. Symmetric cryptography

    Symmetric encryption uses the same key for encryption and decryption. Fast, but the key must be shared securely.

    AlgorithmKey sizeBlock sizeStatus
    DES56 bits64 bitsBroken — brute-forceable
    3DES (Triple DES)112/168 bits64 bitsLegacy; being deprecated
    AES128/192/256 bits128 bitsCurrent standard
    Blowfish32–448 bits64 bitsLegacy; replaced by Twofish
    RC4VariableStream cipherBroken; removed from TLS

    AES (Advanced Encryption Standard) is the gold standard. It uses substitution-permutation network (SPN) structure with 10/12/14 rounds for 128/192/256-bit keys.

    Block cipher modes:

    • ECB: each block encrypted independently — insecure (patterns visible)
    • CBC: each block XORed with previous ciphertext — needs IV
    • CTR: turns block cipher into stream cipher — parallelisable
    • GCM: CTR + authentication tag — provides both encryption and integrity
    Number of keys needed for n parties (symmetric): n(n−1)/2
    10 users → 10×9/2 = 45 keys needed
    The key distribution problem is symmetric crypto's Achilles heel: 10 users need 45 keys, 1000 users need ~500,000 keys. This is why asymmetric crypto was invented — to solve key distribution.

    7. Asymmetric cryptography

    Asymmetric (public-key) encryption uses a key pair: public key (shared) and private key (secret). What one key encrypts, only the other can decrypt.

    AlgorithmBased onKey sizeUse
    RSAInteger factorisation2048+ bitsEncryption, digital signatures
    Diffie-HellmanDiscrete logarithm2048+ bitsKey exchange only
    ECCElliptic curve discrete log256+ bitsEncryption, signatures (smaller keys)
    DSADiscrete logarithm1024–3072 bitsDigital signatures only

    RSA key generation (simplified):

    1. Choose two large primes p, q

      n = p × q (modulus), φ(n) = (p−1)(q−1)

    2. Choose e such that 1 < e < φ(n) and gcd(e, φ(n)) = 1

      Common choice: e = 65537. Public key = (n, e).

    3. Compute d = e⁻¹ mod φ(n)

      Private key = (n, d). Encrypt: C = Me mod n. Decrypt: M = Cd mod n.

    Number of keys for n parties (asymmetric): 2n
    10 users → 20 keys (vs 45 for symmetric)

    Hybrid encryption (used in TLS/SSL): use asymmetric to exchange a session key, then use symmetric (AES) for the bulk data. Combines the best of both worlds.

    Asymmetric crypto is ~1000× slower than symmetric. That's why real systems never encrypt bulk data with RSA — they use hybrid encryption. TLS handshake = RSA/ECDH for key exchange, then AES-GCM for the session.

    8. Hashing and digital signatures

    A hash function maps arbitrary-length input to a fixed-length digest. Properties: deterministic, fast, one-way (pre-image resistant), collision-resistant.

    AlgorithmOutputStatus
    MD5128 bitsBroken — collisions found
    SHA-1160 bitsDeprecated — collisions demonstrated
    SHA-256256 bitsCurrent standard (SHA-2 family)
    SHA-3VariableLatest standard (Keccak-based)

    Digital signature process:

    1. Sender hashes the message → digest

      H(M) = digest (e.g. 256-bit SHA-256 hash)

    2. Sender encrypts digest with their private key → signature

      S = Eprivate(digest)

    3. Sender sends message + signature
    4. Receiver decrypts signature with sender's public key → digest', then hashes the received message → digest''

      If digest' = digest'' → message is authentic and unaltered.

    Digital signature provides: authentication (verifies sender), integrity (detects tampering), non-repudiation (sender cannot deny). It does not provide confidentiality — the message is not encrypted.

    MAC (Message Authentication Code): uses a shared secret key + hash (HMAC). Provides integrity and authentication but NOT non-repudiation (both parties know the key).

    HMAC(K, M) = H( (K XOR opad) || H( (K XOR ipad) || M ) )
    opad = 0x5c repeated to block size, ipad = 0x36 repeated
    Digital signature (private key) = authentication + integrity + non-repudiation
    HMAC (shared key) = authentication + integrity, but NO non-repudiation
    Digital signatures = hash + asymmetric encryption of the hash. They prove WHO sent a message and that it wasn't CHANGED. HMAC proves integrity but not identity (both sides have the same key, so either could have created it).

    9. Authentication and access control

    Authentication factors:

    FactorTypeExamples
    Something you knowKnowledgePassword, PIN, security question
    Something you havePossessionSmart card, OTP token, phone
    Something you areInherenceFingerprint, retina, face
    Somewhere you areLocationGPS, IP geolocation

    Multi-factor authentication (MFA) requires two or more different factors. Using two passwords is NOT MFA (same factor type). Password + OTP IS MFA (knowledge + possession).

    Access control models:

    ModelAccess based onExample
    DAC (Discretionary)Owner's discretionFile permissions in Unix
    MAC (Mandatory)Security labels/clearanceMilitary: Top Secret, Secret, Confidential
    RBAC (Role-based)User's role in organisationBanking: Teller, Manager, Auditor
    ABAC (Attribute-based)Attributes (user, resource, environment)Access during business hours only

    Password storage: never store plaintext passwords. Hash with a salt (random per-user value) using a slow hash function (bcrypt, scrypt, Argon2). The salt prevents rainbow table attacks.

    RBAC is the most relevant model for banking exams. Bangladesh Bank uses role-based access: a teller can process transactions but cannot approve loans; a manager can approve within limits; an auditor has read-only access to all records.

    10. Network defence and governance

    Defensive technologies:

    TechnologyFunctionPlacement
    FirewallFilter traffic based on rules (IP, port, protocol)Network perimeter
    IDS (Intrusion Detection)Detect and alert on suspicious activityNetwork or host
    IPS (Intrusion Prevention)Detect AND block suspicious activityInline (can drop packets)
    WAF (Web Application Firewall)Filter HTTP traffic; block SQL injection, XSSIn front of web servers
    VPNEncrypted tunnel over public networkSite-to-site or remote access
    DMZBuffer zone between public and private networksBetween two firewalls
    SIEMCentralized log collection, correlation and alertingSecurity operations centre

    Security governance frameworks:

    • ISO 27001: Information Security Management System (ISMS) standard
    • NIST Cybersecurity Framework: Identify, Protect, Detect, Respond, Recover
    • PCI-DSS: Payment Card Industry Data Security Standard
    • COBIT: IT governance framework

    PKI (Public Key Infrastructure) manages digital certificates. Components: Certificate Authority (CA), Registration Authority (RA), Certificate Revocation List (CRL). The CA signs certificates binding a public key to an identity.

    IDS detects but doesn't act; IPS detects and blocks. A common analogy: IDS is a security camera (alerts you), IPS is a security guard (stops the intruder). WAF is specifically for web application attacks (Layer 7).

    S3 How does a digital signature work? What security properties does it provide? standard repeat
    1. Signing

      Sender: Hash(message) → digest → Encrypt(digest, private_key) → signature. Send message + signature.

    2. Verification

      Receiver: Decrypt(signature, sender's public_key) → digest₁. Hash(received message) → digest₂. If digest₁ = digest₂ → valid.

    Properties provided:

    • Authentication: only the private key holder could have signed
    • Integrity: any change to the message changes the hash → verification fails
    • Non-repudiation: signer cannot deny signing (only they have the private key)

    Note: digital signatures do NOT provide confidentiality — the message is sent in plaintext.

    S4 What is SQL injection? How can it be prevented? standard repeat

    SQL injection inserts malicious SQL into user input that gets executed by the database.

    Example: Login form with:

    SELECT * FROM users WHERE name='$input' AND pass='$pass'

    If input = ' OR 1=1 --, the query becomes:

    SELECT * FROM users WHERE name='' OR 1=1 --' AND pass=''

    This returns all users → attacker bypasses authentication.

    Prevention:

    • Parameterised queries (prepared statements) — the #1 defence
    • Input validation and sanitisation
    • Stored procedures with parameterised inputs
    • Least privilege database accounts
    • WAF to detect and block SQLi patterns

    S10 Explain the Diffie-Hellman key exchange. Why is it vulnerable to MITM? standard repeat
    1. Agree on public values p (prime) and g (generator)
    2. Alice picks secret a, sends A = ga mod p
    3. Bob picks secret b, sends B = gb mod p
    4. Both compute shared secret: Alice: Ba mod p = gab mod p. Bob: Ab mod p = gab mod p

    MITM vulnerability: Diffie-Hellman has no authentication. An attacker (Eve) can perform two separate DH exchanges — one with Alice, one with Bob — establishing different shared secrets with each. Eve then relays and reads all traffic.

    Fix: authenticate the key exchange — sign the DH parameters with RSA/ECDSA certificates (as done in TLS).

    P1 How many symmetric keys are needed for 50 users to communicate securely? How many asymmetric key pairs? practice
    Symmetric: n(n−1)/2 = 50 × 49 / 2 = 1,225 keys
    Asymmetric: 2n = 2 × 50 = 100 keys (50 pairs)

    This dramatic difference is the key distribution advantage of asymmetric cryptography.

    P2 RSA key generation: p=7, q=11. Find n, φ(n), and if e=13, find d. practice
    n = p × q = 7 × 11 = 77
    φ(n) = (p−1)(q−1) = 6 × 10 = 60
    Find d: e × d ≡ 1 (mod 60) → 13d ≡ 1 (mod 60)
    13 × 37 = 481 = 8 × 60 + 1 → d = 37

    Public key: (77, 13). Private key: (77, 37).

    Encrypt M=2: C = 213 mod 77 = 8192 mod 77 = 30.

    Decrypt: M = 3037 mod 77 = 2 ✓

    P4 What is a DMZ? Why is it important for banking networks? practice

    A DMZ (Demilitarised Zone) is a network segment between two firewalls that hosts public-facing services (web servers, email gateways) while isolating the internal network.

    Architecture: Internet → Firewall 1 → DMZ → Firewall 2 → Internal Network

    Why it matters for banking:

    • Internet banking portal sits in DMZ — accessible to customers but isolated from core banking
    • If DMZ is compromised, attacker still faces Firewall 2 before reaching internal systems
    • Email servers in DMZ prevent direct external access to internal mail systems
    • Regulatory compliance (PCI-DSS) requires network segmentation

    P6 What is ransomware? Describe the WannaCry attack and its impact. practice

    Ransomware encrypts the victim's files with a key only the attacker holds, then demands payment (usually cryptocurrency) for the decryption key.

    WannaCry (May 2017):

    • Exploit: EternalBlue (SMBv1 vulnerability in Windows, MS17-010)
    • Spread: Self-propagating worm — spread across networks without user interaction
    • Impact: 200,000+ computers in 150 countries; NHS (UK) hospitals disrupted
    • Ransom: $300 in Bitcoin per machine
    • Kill switch: discovered by a researcher who registered the domain the malware checked

    Prevention: patch management, offline backups, network segmentation, email filtering, user training.

    P8 What is PKI? Explain the role of Certificate Authority, digital certificate and CRL. practice

    PKI (Public Key Infrastructure) is the framework that manages digital certificates and public-key encryption.

    • Certificate Authority (CA): trusted entity that issues and signs digital certificates. Verifies the identity of the certificate requester.
    • Digital Certificate (X.509): binds a public key to an identity. Contains: subject name, public key, CA's signature, validity period, serial number.
    • Registration Authority (RA): verifies identity before CA issues certificate.
    • Certificate Revocation List (CRL): list of certificates revoked before expiry. Alternative: OCSP (Online Certificate Status Protocol) for real-time checking.

    Trust chain: Root CA → Intermediate CA → End-entity certificate. Browsers trust root CAs pre-installed in their certificate store.

    P10 Why should passwords never be stored in plaintext? Explain salted hashing. practice

    Why not plaintext: if the database is breached, all passwords are immediately compromised. Users often reuse passwords across services, so one breach cascades.

    Hashing: store H(password) instead. Even if breached, the attacker only gets hashes, which are one-way (cannot reverse to get the password).

    Problem with plain hashing: attackers pre-compute hashes of common passwords (rainbow tables). Two users with the same password have the same hash.

    Salted hashing: generate a random salt per user, store H(salt + password) along with the salt. Even identical passwords produce different hashes.

    User A: salt=x7k2, stored = H("x7k2" + "password123")
    User B: salt=m9p1, stored = H("m9p1" + "password123")
    Same password → completely different stored hashes

    Best practice: use bcrypt, scrypt or Argon2 — intentionally slow hash functions that make brute-force attacks impractical.
