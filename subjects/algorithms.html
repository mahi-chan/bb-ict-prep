    Any polylogarithm beats any positive power of n; any polynomial beats any exponential; and n! beats every simple exponential. log(n!) = Θ(n log n), which is why the comparison-sort bound has that shape.

    The 5n and the 100 have not been ignored as an approximation — they genuinely stop mattering, because they are swallowed by the constants c₁ and c₂ that the definition permits. That is what "asymptotic" means.

    Amortised analysis

    The cost of a sequence of operations averaged over the sequence — not the same as average-case analysis, because no probability is involved. The classic example is a dynamic array that doubles when full: most appends cost O(1), an occasional one costs O(n) to copy, but n appends cost O(n) in total, so the amortised cost is O(1).

    • Aggregate method — bound the total cost of n operations, divide by n.
    • Accounting method — charge each cheap operation a little extra and store the credit to pay for a later expensive one.
    • Potential method — define a potential function Φ on the data structure; amortised cost = actual cost + ΔΦ.

    2. Recurrences and the Master theorem

    Master theorem For T(n) = a·T(n/b) + f(n), with a ≥ 1, b > 1, compare f(n) against n^(log_b a): Case 1: f(n) = O( n^(log_b a − ε) ) for some ε > 0 → T(n) = Θ( n^(log_b a) ) the leaves dominate Case 2: f(n) = Θ( n^(log_b a) · logᵏ n ) for some k ≥ 0 → T(n) = Θ( n^(log_b a) · log^(k+1) n ) every level costs the same Case 3: f(n) = Ω( n^(log_b a + ε) ) for some ε > 0 and a·f(n/b) ≤ c·f(n) for some c < 1 (regularity condition) → T(n) = Θ( f(n) ) the root dominates
    Where n^(log_b a) comes from — the recursion tree

    The theorem looks arbitrary until you see what it is comparing. Draw T(n) = 2T(n/2) + n: at every level the problems halve but there are twice as many of them.

    n^(log_b a) is simply the number of leaves. With a branches and depth log_b n, the tree has a^(log_b n) = n^(log_b a) leaves. So the theorem asks one question: is the work at the root (that is f(n)) bigger than the work at the leaves, smaller, or the same?

    Four worked applications, one per case
    T(n) = 2T(n/2) + na = 2, b = 2 → log₂2 = 1 → compare f(n) = n against n¹ same order → CASE 2 with k = 0 T(n) = Θ(n log n) — merge sort
    T(n) = 9T(n/3) + na = 9, b = 3 → log₃9 = 2 → compare f(n) = n against n² f is polynomially SMALLER (ε = 1) → CASE 1, leaves dominate T(n) = Θ(n²)
    T(n) = 3T(n/4) + n log na = 3, b = 4 → log₄3 ≈ 0.793 → compare n log n against n^0.793 f is polynomially LARGER → CASE 3, root dominates regularity: 3·(n/4)log(n/4) ≤ (3/4)·n log n ✓ with c = 3/4 T(n) = Θ(n log n)
    T(n) = 2T(n/2) + n log nlog₂2 = 1; f(n) = n log n = Θ(n¹ · log¹ n) → CASE 2 with k = 1 T(n) = Θ(n · log² n)
    The word "polynomially" is doing real work in Cases 1 and 3. It is not enough for f(n) to be smaller than n^(log_b a) — it must be smaller by a factor of n^ε for some fixed ε > 0. That is exactly why T(n) = 2T(n/2) + n/log n escapes the theorem: here n/log n is smaller than n, but only by a logarithmic factor, not a polynomial one, so it falls in the gap between Case 1 and Case 2 and the theorem simply says nothing. Being able to name that gap — and reach for a recursion tree instead — is usually worth more marks than the three cases themselves.

    Recursion-tree method. Draw the tree, compute the cost of one level, multiply by the number of nodes at that level, sum over all levels. For T(n) = 2T(n/2) + n: each of the log₂n + 1 levels costs n, total Θ(n log n).

    Substitution method. Guess the answer, then prove it by induction. To prove T(n) ≤ cn log n for T(n) = 2T(n/2) + n, assume it for n/2 and substitute: T(n) ≤ 2·c(n/2)log(n/2) + n = cn log n − cn + n ≤ cn log n whenever c ≥ 1. ✓

    When the Master theorem does not apply
    • a or b is not constant, or a < 1, or b ≤ 1.
    • f(n) is not positive, or is not monotone.
    • The gap cases: f(n) is smaller than n^(log_b a) but not polynomially smaller — e.g. T(n) = 2T(n/2) + n/log n falls between Case 1 and Case 2 and is untouched by the theorem (the true answer, by other methods, is Θ(n log log n)).
    • Case 3's regularity condition fails.
    • Subproblems are of unequal size, e.g. T(n) = T(n/3) + T(2n/3) + n — use a recursion tree instead (answer Θ(n log n)).

    3. Divide and conquer

    Three steps: divide the problem into subproblems of the same kind, conquer them recursively, combine their answers.

    Merge sort on [38, 27, 43, 3, 9, 82, 10]

    The divide phase does no comparing at all — it just keeps halving until every piece has one element, which is sorted by definition.

    Now merge back up, pairwise:

    Level 3 → 2[38] [27] → [27, 38] [43] [3] → [3, 43] [9] [82] → [9, 82]
    Level 2 → 1[27,38] [3,43] → [3, 27, 38, 43] [9,82] [10] → [9, 10, 82]
    Level 1 → 0[3,27,38,43] [9,10,82] → [3, 9, 10, 27, 38, 43, 82]

    That last merge, one comparison at a time:

    Merging two sorted lists costs Θ(n) because each comparison retires one element permanently. Only the two front elements are ever examined — never the rest — so seven output slots take seven comparisons at most. That single fact is what makes the whole recurrence work: each level does Θ(n) merging work, there are log n levels, and the total is Θ(n log n). And unlike quick sort, this holds for every input, because the split is by position rather than by value and can never be lopsided. The bill is O(n) extra space for the merge buffer — which is exactly why quick sort, being in-place, is often preferred despite its worse worst case.
    C — merge sort
    void merge(int a[], int l, int m, int r) {
    int n1 = m - l + 1, n2 = r - m;
    int L[n1], R[n2], i, j, k;
    for (i = 0; i < n1; i++) L[i] = a[l + i];
    for (j = 0; j < n2; j++) R[j] = a[m + 1 + j];

    i = j = 0; k = l;
    while (i < n1 && j < n2)              /* the table above */
        a[k++] = (L[i] <= R[j]) ? L[i++] : R[j++];
    while (i < n1) a[k++] = L[i++];       /* drain whichever side is left */
    while (j < n2) a[k++] = R[j++];
}

void mergeSort(int a[], int l, int r) {
    if (l >= r) return;                   /* one element — already sorted */
    int m = l + (r - l) / 2;              /* avoids overflow of (l+r)/2   */
    mergeSort(a, l, m);
    mergeSort(a, m + 1, r);
    merge(a, l, m, r);
}
    Input: 38 27 43 3 9 82 10 Output: 3 9 10 27 38 43 82

    L[i] <= R[j] rather than < is what makes merge sort stable: on a tie the left element goes first, preserving the original relative order of equal keys.

    Divide and conquer vs dynamic programming

    Both split a problem into subproblems. In divide and conquer the subproblems are disjoint, so solving each once is natural. In dynamic programming they overlap, so plain recursion re-solves the same subproblem exponentially many times and the answers must be stored. Naive Fibonacci is the standard illustration: T(n) = T(n−1) + T(n−2) + O(1) = Θ(1.618ⁿ) recursively, but Θ(n) with memoisation.

    4. Greedy algorithms

    Build the solution one piece at a time, always taking whatever looks best right now, and never reconsider. A greedy algorithm is correct only when the problem has both:

    • Greedy-choice property — a globally optimal solution can be reached by making the locally optimal choice at each step.
    • Optimal substructure — an optimal solution contains optimal solutions to its subproblems.

    Eleven activities compete for one lecture hall. Pick the largest set that do not overlap.

    Start130535688212

    They are already sorted by finish time — do this first, always. The whole algorithm is then one pass.

    1. Take A1 (1 – 4)

      The first activity in finish order is always taken. The hall is now busy until 4.

    2. Scan for the next start ≥ 4

      A2 starts at 3 ✗, A3 at 0 ✗, A4 starts at 5 ✓ — take it. Busy until 7.

    3. Next start ≥ 7

      A5 (3) ✗, A6 (5) ✗, A7 (6) ✗, A8 starts at 8 ✓ — take it. Busy until 11.

    4. Next start ≥ 11

      A9 (8) ✗, A10 (2) ✗, A11 starts at 12 ✓ — take it. Nothing follows.

    Answer{A1, A4, A8, A11} — 4 activities, and no set of 5 exists
    Choosing the earliest finish leaves the most room for everything else. That is the entire proof idea. Any other first choice ends no earlier, so it can only make the remaining interval smaller — never larger — and an optimal solution using it can be rewritten to use the earliest-finishing activity instead without getting worse. Compare the tempting alternatives on this same data: earliest start takes A3 (0 – 6), which alone blocks A1 and A2 and yields only {A3, A7, A11} = 3. Shortest duration fails elsewhere — activities (0,10), (9,11), (10,20) tempt it into the 2-hour middle one, which collides with both others and gives 1 instead of 2. Greedy is not "take the obvious thing"; it is "prove which obvious thing".
    Where greedy fails — quote one of these

    Coin change. With denominations {1, 6, 10} and a target of 12, greedy takes 10 + 1 + 1 = 3 coins. The optimum is 6 + 6 = 2 coins. Greedy is optimal only for canonical systems such as {1, 5, 10, 20, 50, 100}.

    0/1 knapsack. Capacity 10 with items (w 6, v 30 → ratio 5), (w 5, v 20 → 4), (w 5, v 20 → 4). Greedy takes the ratio-5 item, leaving capacity 4 which nothing fits, for a value of 30. The optimum takes both ratio-4 items for 40. Indivisibility is what breaks the greedy-choice property; the fractional version, where the last item can be cut, is greedily optimal.

    6. Backtracking and branch and bound

    Build a solution incrementally; the moment a partial solution cannot possibly be completed, abandon it and step back. Conceptually it is a DFS of the state-space tree with pruning.

    4-queens, every step including the dead ends

    Place one queen per row — that constraint is free, since two queens in a row always attack. The only decision per row is which column, and the test is: no earlier queen shares this column or a diagonal.

    Pruning is what separates backtracking from brute force. Trying every arrangement of 4 queens on 16 squares is C(16,4) = 1820 boards. Fixing one queen per row cuts it to 4⁴ = 256. Backtracking then examines far fewer than that, because a dead end at row 3 discards all of that branch's row-4 possibilities without ever generating them — step 4 above kills four boards at once, step 7 another four. The saving compounds with board size, which is how the same method reaches 8-queens and Sudoku.

    Note also what happens at step 8: rows 3 and 2 are exhausted, so the algorithm backtracks two levels and changes row 1. Backtracking is not "undo one move" — it is "return to the most recent decision that still has an untried option".

    A spanning tree of V vertices always has exactly V − 1 edges — here 4 — so the moment you have that many you can stop. The cycle test is what a union-find structure answers in near-constant time, which is why Kruskal costs O(E log E) with the sort dominating.

    Why Dijkstra needs non-negative weights. It finalises a vertex as soon as that vertex is the closest unvisited one, and never revisits it. That is valid only if extending a path can never reduce its length. A single negative edge can make a later, longer-looking route shorter than an already-finalised distance.

    Why Bellman-Ford needs V−1 passes. A shortest path in a graph with no negative cycle uses at most V−1 edges. After pass k, every shortest path using at most k edges has been found, so V−1 passes settle everything. If a V-th pass still improves some distance, a shorter path with V edges exists, which forces a repeated vertex — a negative cycle.

    MST correctness — the cut property. For any partition of the vertices into two non-empty sets, the lightest edge crossing the partition is in some MST. Kruskal applies this globally in weight order; Prim applies it to the cut between the tree grown so far and the rest. Both are therefore correct, and when all weights are distinct the MST is unique.

    Max flow — Ford-Fulkerson. While an augmenting path exists from source to sink in the residual graph, push the bottleneck capacity along it and update residual capacities in both directions. The max-flow min-cut theorem states that the maximum flow equals the capacity of the minimum s–t cut. With BFS used to find the augmenting path (the Edmonds-Karp refinement) the running time is O(V·E²), independent of the capacity values.

    The text pointer never moves backwards, and that single property is the whole O(n) bound.     Rabin-Karp generalises cheaply to searching for many patterns at once and is the basis of plagiarism detection; Boyer-Moore is what most practical text search uses because its skips grow with pattern length.

    Reducing mod m at every step is not an optimisation — it is what makes the calculation possible. Computing 3¹³ in full gives 1,594,323, which is fine; but RSA uses exponents of hundreds of digits, and a^n for those would have more digits than there are atoms in the universe. Squaring modulo m keeps every intermediate below m², so the numbers stay the size of the key rather than the size of the exponent. Together with Euclid's algorithm — which is also O(log n) — this is why public-key cryptography is fast enough to run on a payment terminal.

    Modular exponentiation computes a^n mod m in O(log n) multiplications by squaring: if n is even, a^n = (a^(n/2))²; if odd, a^n = a · a^(n−1). Reducing mod m at every step keeps the numbers small — computing a^n first and then reducing would overflow immediately.

    10. Complexity classes

    P
    Decision problems solvable in polynomial time by a deterministic machine. Sorting, shortest path, matching, primality.
    NP
    Decision problems whose "yes" answers can be verified in polynomial time given a certificate. Equivalently, solvable in polynomial time by a non-deterministic machine.
    NP-hard
    At least as hard as every problem in NP: every NP problem reduces to it in polynomial time. Need not be in NP and need not be a decision problem — the halting problem is NP-hard.
    NP-complete
    In NP and NP-hard. The hardest problems that are still verifiable in polynomial time.
    Co-NP
    Problems whose "no" answers can be verified in polynomial time.
    Canonical NP-complete problems — name two or three in any answer
    ProblemQuestion
    SAT / 3-SATIs there an assignment satisfying this Boolean formula? Cook-Levin proved SAT was the first NP-complete problem.
    Travelling salesman (decision)Is there a tour of length ≤ k visiting every city once?

    Polynomial-time reduction. A ≤ₚ B means any instance of A can be transformed into an instance of B in polynomial time such that the answers agree. It says B is at least as hard as A. To prove a new problem X is NP-complete: (1) show X ∈ NP by giving a polynomial-time verifier, then (2) reduce a known NP-complete problem to X. The direction matters — reducing X to a known problem proves nothing about X's hardness.

    Undecidable is not the same as intractable

    The halting problem — decide whether an arbitrary program halts on an arbitrary input — has no algorithm at all, at any cost. Turing's diagonal argument: if a decider H existed, build D(p) that loops when H(p, p) says "halts" and halts otherwise; asking D(D) contradicts itself either way. NP-complete problems, by contrast, are perfectly decidable — just not known to be decidable quickly.

    Living with NP-hardness. Approximation algorithms give a guaranteed ratio — the greedy vertex-cover algorithm is a 2-approximation, and metric TSP has a 1.5-approximation (Christofides). Randomised algorithms trade certainty for speed: Las Vegas algorithms are always correct with random running time (randomised quick sort); Monte Carlo algorithms run in bounded time but may err with small probability (Miller-Rabin). Heuristics — simulated annealing, genetic algorithms — offer no guarantee but work well in practice.

    (c) Why KMP is linear

    1. The text pointer never moves backwards. Look at the trace: on every mismatch only j is reduced; i either stays or increases. Since i runs from 0 to n−1 and never rewinds, there are at most n forward moves.

    2. The fallbacks are bounded too. Each successful character comparison increases j by exactly 1, and each fallback decreases it by at least 1. j can therefore fall at most as many times as it has risen — at most n times overall. Total work is O(n) + O(n) = O(n), plus O(m) to build the LPS array, giving O(n + m).

    3. The naive algorithm re-reads. On a mismatch it slides the pattern one position right and restarts comparing from the pattern's first character, so text characters are examined repeatedly. Worst case T = AAAA…A with P = AAA…AB: every one of the n − m + 1 alignments compares m characters before failing on the last, giving O(m(n − m + 1)) = O(mn). KMP avoids this because the LPS array already records how much of the pattern is guaranteed to still match after a shift.

    Backtracking versus brute force

    Placing 4 queens anywhere on 16 squares: C(16, 4) = 1,820 arrangements One queen per row, all column choices: 4⁴ = 256 One per row and column (permutations): 4! = 24 Backtracking with pruning: a few dozen node visits, most branches cut at depth 2 or 3

    The saving is not asymptotic — N-queens by backtracking is still O(N!) in the worst case — but the constant is enormous, because a conflict detected at row 2 discards every completion of that prefix at once. Brute force would have generated and tested each of them individually.

    Two solutions: (2, 4, 1, 3) and (3, 1, 4, 2), written as the column of the queen in each row. Backtracking prunes whole subtrees at the first conflict instead of enumerating all 256 row-wise placements.

    (d) Extended Euclid in RSA

    RSA picks a public exponent e and needs a private exponent d with e·d ≡ 1 (mod φ(n)) — that is, d is the modular multiplicative inverse of e. Writing the congruence as e·d + φ(n)·k = 1 makes it exactly a Bézout equation, so extended Euclid produces d directly, in O(log φ(n)) steps. It also settles existence: an inverse exists if and only if gcd(e, φ(n)) = 1, which is why e must be chosen coprime to φ(n).

    (b) Polynomial-time reduction

    A ≤ₚ B means: there is a polynomial-time function f such that for every instance x, x is a YES instance of A ⇔ f(x) is a YES instance of B Reading: "B is at least as hard as A" — a fast solver for B gives a fast solver for A.

    1. Step 1 — show X ∈ NP. Give a certificate and a polynomial-time verifier for it. For vertex cover, the certificate is the set of k vertices; the verifier walks every edge and checks that at least one endpoint is in the set — O(E).

    2. Step 2 — show X is NP-hard. Pick a known NP-complete problem Y and construct a polynomial-time reduction Y ≤ₚ X. The direction is the part candidates reverse: reducing X to a known hard problem proves nothing about X.

    Cook and Levin bootstrapped the whole theory by proving SAT NP-complete directly from the definition of a non-deterministic Turing machine. Every later proof reduces from something already known.

    (c) Examples

    • Three NP-complete: 3-SAT (is a 3-CNF formula satisfiable?), vertex cover (is there a cover of size ≤ k?), Hamiltonian cycle (is there a cycle visiting every vertex once?). Also clique, subset sum, graph colouring and the decision form of 0/1 knapsack.
    • NP-hard but not in NP: the halting problem. It is NP-hard, but it is undecidable — no algorithm decides it at all, so there is no verifier and it cannot be in NP. The optimisation form of TSP ("find the shortest tour") is another: it is not a decision problem, so it is outside NP by definition, though its decision form is NP-complete.

    (d) Significance for banking cryptography

    Public-key cryptography rests on problems that are easy in one direction and believed hard in the other: RSA on integer factorisation, Diffie-Hellman and ECC on the discrete logarithm. Neither is known to be NP-complete — they sit in NP but are suspected to be strictly between P and NP-complete — yet the same logic applies. If an efficient algorithm were found for them, then TLS, digital signatures on cheques and instruments, SWIFT message authentication, PIN encryption and the certificate chain behind internet banking would all fail at once.

    Two caveats worth a sentence in the answer. First, P = NP would not automatically break RSA, because factorisation is not known to be NP-complete — but it would remove any hope of a proof of hardness. Second, the practical near-term threat is not P = NP at all but quantum computing: Shor's algorithm factors integers and computes discrete logarithms in polynomial time on a quantum machine, which is why central banks and standards bodies are now migrating to post-quantum algorithms. Symmetric ciphers such as AES are far less affected — Grover's algorithm only halves the effective key length, so AES-256 remains sound.

    P ⊆ NP; NP-complete = NP ∩ NP-hard. Proving X NP-complete needs (1) X ∈ NP and (2) a reduction from a known NP-complete problem to X. The halting problem is NP-hard but not in NP because it is undecidable.
